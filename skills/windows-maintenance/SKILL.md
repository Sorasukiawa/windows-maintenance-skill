# Windows 电脑维护

把检查、更新、整理和清理推进到分项可验收，并留下中文维护记录。
核心是区分“查询完成”“实际状态”“变更成功”和“稳定性验证”。
提供可运行的只读采集、目录分类和前后对比脚本；实施步骤按实际对象与授权执行。

## 本地默认与本轮范围

- 维护范围和排除项由用户当次指令及本任务已有授权确定，不把旧任务的临时排除项固化为默认。
- 主板 BIOS/UEFI/AGESA 与其他固件可纳入检查候选；实际刷写仍按具体设备的现有授权、适用性和恢复条件执行。
- 默认中文沟通与记录；命令、错误码、设备 ID 保持原文。
- 先读取当前任务已有报告、证据、进度与授权，重新核验容易变化的状态。
- “检查”先做只读盘点；“更新、整理、清理”允许推进已明确候选的实施与验证。
- 已有授权继续有效，不为每个常规步骤重复询问。
- 大范围用户数据删除、重启、分区改动、硬件调校及具体设备刷写需有对应授权。
- 需要确认时先完成调查、备份方案和适用性核对，使待确认项具体可审阅。
- 不能静默扩大目标；不因一个项目受阻而停止其他不依赖它的已授权工作。

## 从现有状态继续

1. 定位原始日志、候选清单、已执行命令和真实后验结果。
2. 检查是否正在安装、传输或运行维护任务，以及是否待重启。
3. 比对当前版本、活动进程、设备绑定与报告版本，避免重复安装。
4. 将工作划分为已完成、待执行、需补证、失败或等待必要输入。

若原报告来自旧脚本或出现 Success 与内容矛盾，先读
[证据与采集](references/evidence.md)，修正具体采集缺口。
不要重做无变化且已有可靠证据的全部检查。

## 只读盘点

围绕用户目标收集下列信息，任务窄时缩减范围：

完整维护可先运行 [Collect-MaintenanceSnapshot.ps1](scripts/Collect-MaintenanceSnapshot.ps1)
生成 JSON 与中文报告；只查空间使用 [Measure-MaintenanceDirectories.ps1](scripts/Measure-MaintenanceDirectories.ps1)。
命令、覆盖范围及稳定数据格式见 [采集与对比工具](references/automation.md)。
脚本只读取本地登记与设备信息；更新候选、活动版本、完整性和固件适用性按下述流程补查。

| 范围 | 有用证据 |
|---|---|
| 硬件 | 主板/CPU/RAM/GPU/磁盘/外设精确型号，PnP 实例 ID |
| Windows | 版本与构建、更新候选、待重启、恢复环境、系统完整性 |
| 驱动 | 当前设备绑定 INF 与版本、问题码、签名和官方适用性 |
| 软件 | 卸载登记、活动可执行文件版本、自更新状态与精确包 ID |
| 稳定性 | 故障时间、停止码、原始事件、转储、相关配置 |
| 整理 | 自启动真实启用状态、缺失目标、目录用途与逻辑大小 |

避免用 Win32_Product 枚举软件，以免触发 MSI 一致性修复。
优先内置命令、已有厂商工具和官方来源，不为维护额外要求安装插件。
“未检出”只适用于本次查询的来源和窗口，不等于所有渠道均为最新。
禁用设备、并存运行库或后台服务先按用途判断，不能自动当成故障或垃圾。

## 实施顺序

### 1. 先处理阻碍维护的异常

有系统损坏时，先保存 CBS/DISM 日志与可用恢复资料。
在授权范围内按 DISM RestoreHealth → SFC scannow 修复，再核验实际结论。
修复未通过时暂停依赖健康组件存储的清理，继续可独立完成的工作。
有黑屏、死机或异常重启时，保留转储、原始事件及当前驱动/调校配置。
短时正常只报告观察窗口；维护成功不等于故障根因已修复。
详见 [更新与修复](references/update-repair.md)。

### 2. 更新已确认适用的项目

读取并记录当前实际版本、候选来源、安装方式与回退资源。
软件按精确 ID 或自带更新器逐项执行，保存安装器及必要配置。
安装器返回后检查实际安装版本；旧进程仍活动则分别报告磁盘版和活动版。
驱动更新核对硬件 ID、OS/架构、包签名和设备绑定，备份对应旧包。
冷却、风扇、水泵、RGB/LCD 或远程连接相关软件，要先确认配置与可用控制方式。
一次只改变影响同一故障归因的一项；普通无关软件可按独立范围推进。
固件只在具体设备授权与完整适用性证据齐备后刷写。
不要以软件版本、USB 显示名称或其他型号固件推断设备内部固件。

### 3. 整理和清理

按 [清理与回退](references/cleanup.md) 筛选具体对象和受支持操作。
先处理确定失效的启动记录、无用安装解压包和未占用的可再生缓存。
删除前记录完整绝对路径、用途、候选字节数、恢复方法及所需程序状态。
目录统计跳过重解析点；访问受限或超时标为不完整；父子项不能直接相加。
驱动库和组件存储通过受支持工具管理，先确认健康及保留回退资源。
着色器缓存清理可能造成重新编译卡顿，不把它设为例行“提速”。
项目、模型、录像、存档、账户资料和 Codex 定制内容按用户数据处理。
占用中的项目记录跳过；不为清理强杀所有程序或更改系统目录权限。

### 4. 验证并交付

每项验证应对应其实际变化：

| 变更 | 最少验收证据 |
|---|---|
| 软件 | 新版本实际存在、签名/来源可信、目标进程或功能状态 |
| 驱动 | 安装结果、目标设备绑定新版本、问题码与相关功能 |
| 系统修复 | 修复原始结果及随后健康结论；重启要求单独列出 |
| 清理 | 实际处理清单、失败/跳过、候选逻辑字节与卷空闲变化 |
| 自启动 | 原值备份、目标条目确已变化、恢复方法 |
| 固件 | 厂商工具报告完成及设备重新读取的内部版本 |

最终简洁说明实际变化、验证结果、剩余事项和需要用户完成的具体动作。
用 [Compare-MaintenanceSnapshots.ps1](scripts/Compare-MaintenanceSnapshots.ps1) 对比同机、同来源、完整采集的前后快照。
`Incomparable` 保持未比较；观测中的 Added/Removed 不能直接当成更新成功或软件卸载。
同时提供中文 Markdown 维护记录，记录结构见 [证据与采集](references/evidence.md)。
未验证的应用功能、重启后状态或游戏稳定性直接标明。

## 底层辅助与验证

[Maintenance.ReadOnly.psm1](scripts/Maintenance.ReadOnly.psm1) 保留三个底层只读辅助函数：

- `Invoke-MaintenanceRead`：收集 PowerShell 查询数据与错误，空数据单独标记。
- `Get-MaintenanceTreeSize`：有时限的目录逻辑大小，跳过重解析点并标记完整性。
- `Resolve-MaintenanceChildPath`：核验现存本地绝对路径严格位于指定根目录内。

使用示例和边界见 [证据与采集](references/evidence.md)。
路径校验只证明位置；文件可删除性仍须依据用途、授权、占用和恢复要求判断。
新增工具回归检查见 [Test-Maintenance.ps1](scripts/Test-Maintenance.ps1)，只在指定工作目录创建测试夹具和报告。
