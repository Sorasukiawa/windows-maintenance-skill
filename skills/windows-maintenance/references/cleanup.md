# 清理、整理与回退

## 候选分类

| 对象 | 处理依据 |
|---|---|
| 旧临时文件 | 年龄只是筛选，检查程序占用与用途，跳过拒绝访问项 |
| 软件解压目录/安装器 | 确认安装已结束、软件工作正常及可重新取得官方包 |
| 浏览器 Cache/Code Cache/GPUCache | 正常退出目标浏览器后处理具体缓存；保留登录、密码、书签和完整资料目录 |
| 着色器缓存 | 有空间需求或缓存故障线索再清；记录重新编译和首次卡顿影响 |
| 无效自启动 | 核对已启用状态、完整命令、目标是否缺失及是否暂不可用；先备份精确条目 |
| 模型、录像、游戏、下载、工程 | 用户数据，按明确对象与用途授权；不能仅凭大小、旧日期或相似文件名删除 |
| `.codex`、运行时、插件、skills | 可能是定制和依赖；依据所有权与引用关系处理，不当普通缓存全删 |

StartupApproved、任务状态与 Run 项同时判断；已禁用项不能算“本轮优化后禁用”。
缺失的程序目标可能在可移除盘/网络位置，先区别临时不可达与明确残留。
自启动条目导出或保存类型和值之后只改目标项；验证实际结果并提供精确恢复方法。
保留系统运行库、WebView、音频/键盘/反作弊等依赖，除非已核实对应软件及用户范围。

## 文件操作与容量

先列明本轮具体根目录和候选文件，核验最后解析的绝对路径；不得把卷根或父目录当成计算出的删除目标。
检查根、目标及祖先路径中的重解析点。不要跟随连接重复扫描/删除其目标，不能只过滤枚举出的子目录。
PowerShell 路径参数使用 LiteralPath；Windows 文件移动/删除保持在一个 shell 内，不能把枚举结果拼入 cmd 命令。
修改前再次读取最终路径与属性；本 skill 的路径助手不是文件锁，也不证明数据可丢弃。
不要为清理取得整个 Windows 目录的所有权、取消 ACL 或杀掉所有占用程序。

同盘隔离目录可提供撤销，实际空闲空间不会增加；正式删除或跨盘迁移需按真实结果报告。
记录候选逻辑字节、成功处理逻辑字节、跳过/失败及同一卷空闲差值，避免承诺统计值全部可回收。
目录逻辑大小可能包含硬链接、多重扫描、压缩差异；父/子项和链接/目标不能直接相加。
带访问错误或超时的统计为下限，不使用 Complete=true 包装不完整采集。
长期修复或游戏过程有后台写入，空闲空间前后差可能与处理量不同，分别报告。

## 系统与驱动库

先确认完整性修复和相关更新验证通过，再依据 DISM AnalyzeComponentStore 决定组件清理。
使用 Windows 支持的 StartComponentCleanup；不直接删除 WinSxS，也不使用 ResetBase 牺牲现有更新回退。
StartComponentCleanup 会立即清理被替代组件，区别于计划任务的等待期；操作与影响记入日志。
参考：[微软 WinSxS 清理说明](https://learn.microsoft.com/en-us/windows-hardware/manufacture/desktop/clean-up-the-winsxs-folder?view=windows-11)。

DriverStore 只通过受支持的包管理工具处理。先核对包是否仍绑定设备，保留当前包和有依据的回退包。
系统近期有显示故障时保留相关驱动资源，不能为清理收益删掉全部旧版本。
没有确切理由不添加 `/force` 或 `/uninstall` 扩大删除影响；不要手工删除 FileRepository。
Windows Installer/Package Cache、pagefile、恢复分区、未分配空间不是常规垃圾。

## 有故障时保留的资料

系统损坏或黑屏尚未定位时，保留本轮 CBS、DISM、EVTX、WER、CrashDumps、Minidump、LiveKernelReports。
不清空日志以制造“零异常”，不为释放空间缩小转储所需的分页文件。
可在保留必要原始证据后按本轮明确范围归档历史日志，但不删除正在写入的系统日志。
报告区分“已保存文件”“恢复路径已核对”和“已演练恢复”，不混称可回退。
